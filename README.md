# HQ Access Control Bot

Бот-привратник на aiogram 3.28. Контролирует вход в приватные рабочие группы
проектов: ловит заявку на вступление, сверяет пользователя с белым списком
проекта и автоматически одобряет или отклоняет. Об отказах уведомляет
администратора. Развёрнут на Azure и работает 24/7.

---

## Как это работает

1. У каждой рабочей группы включены «Заявки на вступление» (Request Admin
   Approval) в пригласительной ссылке.
2. Пользователь жмёт ссылку и подаёт заявку.
3. Telegram присылает боту событие `chat_join_request`.
4. Бот сверяет `user_id` или `@username` со списком доступа этой группы:
   - есть в списке -> мгновенно одобряет, человек в группе за секунду;
   - нет -> отклоняет, шлёт ему «Заявка отклонена», а администратору -
     уведомление, кто и куда пытался войти.

Защита по умолчанию: группа, которой нет в `whitelist.json`, отклоняет всех.

## Команды бота

Для всех:

- `/start`, `/help` - приветствие и справка.
- `/me` - показать свой числовой ID.

Только для администратора (id из `ADMIN_IDS`, в личке с ботом):

- `/add <проект|chat_id> <@user|id> [ещё...]` - добавить участников в проект.
- `/remove <проект|chat_id> <@user|id> [ещё...]` - убрать участников.
- `/reload` - показать текущие списки доступа.
- `/status` - статус, аптайм, число групп и участников.
- `/clear` - очистить переписку с ботом.
- `/id` - узнать `chat_id` (отправить команду в группе).

Меню команд, описание бота и кнопка «Меню» проставляются автоматически при
старте бота.

## Белый список (whitelist.json)

Формат: один блок на группу, ключ - её `chat_id`.

```json
{
  "-1003900046858": {"project": "Brierly", "ids": [1008941473], "usernames": ["@v_lvdnsk"]},
  "-1003938342776": {"project": "PTTC",    "ids": [1008941473], "usernames": ["@vms202"]}
}
```

- `project` - имя проекта (ярлык, бот его показывает; на проверку не влияет).
- `ids` - числовые Telegram ID. Основной способ: ID не меняется.
- `usernames` - запас, с `@` или без, регистр любой.
- Достаточно совпадения по любому из двух списков.

Особенности, которые работают сами:

- **Авто-регистрация групп.** Добавляешь бота в новую группу - он сам заводит её
  в список (пустую) и пишет тебе в ЛС. `/id` руками больше не нужен.
- **Авто-апгрейд.** Когда пущенный по `@username` человек реально заходит, бот
  фиксирует его числовой `id`. Со временем все переходят на надёжную id-привязку,
  и смена ника не ломает доступ.

Правки списка применяются на лету, рестарт не нужен.

## DevOps: как работать с ботом

Всё ниже выполняется на сервере. Сначала подключись к нему по SSH.

### 1. Подключиться к серверу

В PowerShell на своём ПК:

```powershell
ssh -i "$HOME\.ssh\hqbot_key.pem" azureuser@52.177.116.217
```

Выйти с сервера обратно - команда `exit` или Ctrl+D.

> Если ключ перенесёшь и SSH ругнётся «UNPROTECTED PRIVATE KEY FILE», закрой
> права на файл:
> ```powershell
> icacls "ПУТЬ\hqbot_key.pem" /inheritance:r
> icacls "ПУТЬ\hqbot_key.pem" /grant:r "$($env:USERNAME):R"
> ```

### 2. Управление сервисом

```bash
sudo systemctl status hqbot     # состояние (active/running?)
sudo systemctl restart hqbot    # перезапустить (после правки кода или .env)
sudo systemctl stop hqbot       # остановить
sudo systemctl start hqbot      # запустить
sudo systemctl disable hqbot    # убрать из автозапуска
sudo systemctl enable hqbot     # вернуть в автозапуск
```

### 3. Логи

```bash
journalctl -u hqbot -f               # живой поток (Ctrl+C - выйти, бота не трогает)
journalctl -u hqbot -n 50 --no-pager # последние 50 строк
journalctl -u hqbot --since "1 hour ago"   # за последний час
journalctl -u hqbot -p err           # только ошибки
```

Отдельный аудит доступов (кто одобрен/отклонён, кого добавили/убрали):

```bash
tail -n 50 ~/hqbot/access.log        # последние записи
tail -f ~/hqbot/access.log           # живой поток аудита
```

### 4. Обновить код бота (выкатить новую версию)

Поправил `bot.py` у себя на ПК - залей и перезапусти. В PowerShell на ПК:

```powershell
cd "D:\System\SamsungPortableSSD_SW\hq_access_control_bot\hq_access_control_bot"
scp -i "$HOME\.ssh\hqbot_key.pem" bot.py azureuser@52.177.116.217:/home/azureuser/hqbot/
```

Затем на сервере:

```bash
sudo systemctl restart hqbot
journalctl -u hqbot -n 20 --no-pager   # проверить, что поднялся без ошибок
```

Если менял зависимости (`requirements.txt`) - после scp ещё:

```bash
cd ~/hqbot && ./venv/bin/pip install -r requirements.txt && sudo systemctl restart hqbot
```

### 5. Управление участниками

Основной способ - из Telegram, в личке с ботом (безопасно, под локом):

```
/add PTTC @ivan              # добавить
/add Brierly @anna @petr 555 # сразу несколько, по @ или id
/remove PTTC @ivan           # убрать
/reload                      # посмотреть весь список
```

Альтернатива - править файл на сервере (бот подхватит на лету):

```bash
nano ~/hqbot/whitelist.json   # сохранить: Ctrl+O, Enter; выйти: Ctrl+X
```

Менять файл руками лучше, когда нет активного потока заявок, чтобы правка не
пересеклась с авто-записью бота. Через `/add` и `/remove` это исключено.

### 6. Диагностика

Бот не отвечает / не пускает:

```bash
sudo systemctl status hqbot          # сервис вообще жив?
journalctl -u hqbot -n 50 --no-pager # что в логах
```

- `active (running)` нет -> `sudo systemctl restart hqbot`, смотри ошибку в логах.
- В логах `TelegramConflictError` / `409` -> где-то запущена вторая копия с тем же
  токеном (например, локальный `run.bat`). Оставь только серверную, останови
  вторую.
- `BOT_TOKEN пуст` -> на сервере нет/пустой `~/hqbot/.env`.
- Заявка отклоняется, хотя человек должен пройти -> проверь `/reload`: он в нужном
  проекте? `@username` точно совпадает? Надёжнее добавить по числовому `id`.

### 7. Перезагрузка и обслуживание сервера

```bash
sudo reboot                   # перезагрузить сервер; бот поднимется сам
sudo apt update && sudo apt upgrade -y   # обновить пакеты ОС (изредка)
df -h /                       # сколько места на диске
free -m                       # сколько памяти занято
```

### 8. Безопасность

- **Токен** - только в `~/hqbot/.env` на сервере. Никуда не выкладывать. Утёк -
  `/revoke` в @BotFather, новый в `.env`, `sudo systemctl restart hqbot`.
- **SSH-ключ** `hqbot_key.pem` - единственный вход на сервер. Хранить надёжно,
  не шарить. Потеряешь - доступ к серверу только через сброс в Azure-портале.
- **Одна копия на один токен.** Никогда не держи запущенным `run.bat`, пока
  работает сервер - будет конфликт 409.

### 9. Стоимость

Виртуалка B1s + диск ~ £6-7/мес, списывается с кредита подписки Visual Studio
Enterprise - из своего кармана 0. Управление расходами: Azure-портал ->
Cost Management. Остановить списание совсем: в портале остановить (Stop) или
удалить виртуалку `hqbot` и группу `hqbot-rg`.

## Известное ограничение

Письмо отклонённому/одобренному доходит только тем, кто заранее нажал Start у
`@hq_access_control_bot`: Telegram не даёт боту писать первым. Заявка при этом
обрабатывается корректно, теряется только текст уведомления. Фикс: в витрине-хабе
добавь шаг «сначала нажми Start у @hq_access_control_bot, потом подавай заявку».
